# 无言以队 · 舞弊审计调查辅助台

> 金融业**舞弊审计调查岗位** AI 工作助理
> **AI辅助生成 · 不构成调查结论 · 关键判断由调查人员作出**

---

## 一、这是什么

「无言以队」服务于**金融业舞弊审计调查岗位**，把"找数、比对、列清单、写初稿"这些重复性、机械性的准备工作承接过来，把"判断、定性、下结论"完整地留给调查人员。

**定位是辅助而非替代。** 系统不做调查结论、不做责任认定、不做定性判断。所有关键决策、专业判断、案件定性和调查结论，均由舞弊审计调查岗位人员作出。

本系统输出的是**线索**和**提示**，不是**结论**；是**初稿**，不是**定稿**；是**参考分值**，不是**定性意见**。

## 二、快速开始

### 方式一：双击即用（推荐，无需任何安装）

直接双击 **`index.html`**，浏览器打开即可使用**全部功能**。

- 演示数据内联于页面（`PRELOAD_DEMO`），断网亦可运行
- 适用于演示、试用、离线查阅
- 不依赖后端服务

### 方式二：一键启动（含后端安全代理 + 真实数据库）

双击 **`start.bat`**，脚本将自动：

1. 检查 Node.js 环境（未安装时会提示并自动以离线模式打开页面）
2. 首次运行自动安装依赖（`mysql2`）
3. 启动后端安全代理（`http://127.0.0.1:3001`）
4. 打开前端页面

启动后可在页面顶部的「**演示数据 / 连接数据库**」开关中切换数据源。

### 方式三：手动启动

```bash
npm install          # 安装依赖（仅 mysql2）
node server.js       # 启动后端代理
```

然后浏览器访问 `http://127.0.0.1:3001/index.html`，或直接打开 `index.html`。

## 三、七个辅助模块

页面左侧导航固定 7 项 + 第 8 项「测试示例」。每个模块均标注 **【助理辅助】** 与 **【人工决策】** 分工。

| # | 模块 | 功能定位 | 助理辅助 | 人工决策 |
|---|---|---|---|---|
| 1 | **数据聚合台**<br>`data_aggregate` | 按调查主题从 26 张表拉取并关联数据，输出统一口径底稿 | 取数与汇总 | 认定哪些数据纳入调查范围 |
| 2 | **风险信号识别**<br>`risk_signal` | 三步法识别异常交易、资金流向异常、疑似关联交易 | 识别与提示 | 异常是否成立、是否与舞弊相关 |
| 3 | **线索梳理**<br>`clue_sort` | 以涉及主体为主线，四视图呈现 6 要素线索清单 | 组织与排序 | 线索取舍、核查顺序、是否深挖 |
| 4 | **可疑度评估**<br>`risk_score` | 评分卡打分 + 舞弊三角解释，输出参考分值 | 计分与解释 | 最终可疑等级与是否构成舞弊 |
| 5 | **证据核对**<br>`evidence_check` | 五种机械性勾稽核对，输出差异明细与待取证清单 | 核对与差异定位 | 差异性质判断、是否需外部取证 |
| 6 | **报告初稿**<br>`report_draft` | 固定 7 节结构化报告 + 免责声明 + 复核签字位 | 起草与排版 | 结论、定性、表述定稿 |
| 7 | **问答与提醒**<br>`qa` / `reminder` | 解释分析方法与数据口径；提醒未完成核查项 | 解释与提醒 | 全部合规与处置判断 |

### 2.1 风险信号识别：三步法（`hybrid_three_step`）

必须按序执行并分别标注：

1. **第一步 · 规则阈值初筛**（R01–R20）：对全量数据跑规则引擎，规则编号可追溯
2. **第二步 · 指标/比率分析**（M01–M07）：毛利率、费用率、应收周转、票款不一致率、现金交易占比、银企差异率、非工作日占比，输出偏离度（σ）
3. **第三步 · 关联图谱与模型复核**（G01–G07）：环状资金流、共用联系方式/地址、人员关联、实控人密集往来、制单审核同人、审批链完整性

### 2.2 资金流向异常 5 视角（全部启用）

| 视角 | 含义 |
|---|---|
| `round_trip` 资金回流 | 付款方与回款方存在路径闭环或时间邻近的资金回流（含经关联自然人回流） |
| `split_payment` 拆分付款 | 同一收款方/同一事项在短周期内被拆分为多笔，单笔低于审批阈值 |
| `abnormal_time_channel` 异常时间与渠道 | 非工作日交易、大额现金/个人卡收付、渠道分布偏离 |
| `related_party_concentration` 关联方集中 | 资金在疑似关联方之间高度集中 |
| `cash_mismatch` 票款/账实不符 | 发票、合同、订单、入库、付款、银行流水之间金额或时间不匹配 |

### 2.3 关联交易识别口径（`equity_person_substance`）

| 层级 | 内容 | 标注 |
|---|---|---|
| 股权关联 | 共同股东、投资关系、同一法人代表 | 命中前两层标记为「关联交易」线索 |
| 人员关联 | 同一法人、董监高、财务负责人、经办人重合 | 同上 |
| 实质控制 | 同一地址/联系方式/银行账户/开票信息、价格显著偏离公允、无商业实质资金往来 | 仅命中此层标记为「疑似关联交易（待人工确认）」 |

每条命中均标注**命中依据类型**与**可能的误报原因**。

### 2.4 可疑度评估：评分卡 + 舞弊三角（`scorecard_plus_triangle`）

| 维度 | 权重 | 指标示意 |
|---|---|---|
| 压力 Pressure | 30 | 业绩/考核压力、异常资金需求、关联方重大往来 |
| 机会 Opportunity | 45 | 不相容职务未分离、单一人员长期对接、供应商准入不全、审批链不完整、单据勾稽缺失 |
| 借口/合理化 Rationalization | 25 | 价格偏离解释、资金用途说明；**无数据支撑时固定写明"无数据支撑，需调查人员访谈判断"** |

分级：≥70「高度可疑，建议优先核查」；40–69「中度可疑」；<40「低度可疑」；数据不足「信息不足待补充」。

**强制声明**：本分值为规则化参考值，不构成对舞弊事实的认定，最终可疑等级由调查人员确定。

### 2.5 证据核对：五种方法（全部具备）

| 方法 | 内容 |
|---|---|
| `three_way_match` 三单匹配 | 采购订单/订单行 ↔ 入库单 ↔ 进项发票，比对数量、金额、税额、日期顺序（订单≤入库≤发票） |
| `voucher_sampling` 凭证抽凭 | 金额分层 / 异常特征（临近期末、无来源单据号、制单审核同人）抽样，核对 `source_ref` 可追溯性 |
| `cross_system_compare` 跨系统比对 | OA 报销 ↔ 总账凭证 ↔ 银行付款，校验审批链、金额一致性、审批人与收款人重合 |
| `bank_book_reconcile` 银企对账 | 银行流水 ↔ 记账凭证，校验 `voucher_id` 挂接与 `matched` 状态，输出未达账项 |
| `external_confirmation` 外部函证 | 生成函证资料清单与要素初稿，**不触发任何对外发送** |

### 2.6 报告初稿：固定 7 节

1. 报告说明与免责声明（固定文案，置顶）
2. 调查背景与范围
3. 数据来源与分析方法（列出实际使用的表、规则编号、方法名称）
4. 风险信号识别结果（分级汇总表 + 图表）
5. 可疑线索梳理（按主体，含待核查线索清单 6 要素）
6. 证据核对结果与差异说明
7. 待核查事项与建议核查动作（**不含结论性建议**）

**表述口径**（`graded_with_disclaimer`）只用："存在……迹象""提示……可能性""数据显示……与……不一致""建议核查……"。

**固定标注**（封面与页脚均出现）：

```
【声明】本报告由AI助理辅助生成，仅作为舞弊审计调查的辅助分析材料，
不构成调查结论，不构成对任何主体或个人的定性意见。
最终调查结论由调查人员依据职权和专业判断作出。

复核人（签字）：__________   复核日期：____年__月__日
调查负责人（签字）：__________   日期：____年__月__日
```

## 四、交互与输出形式

| 维度 | 覆盖 |
|---|---|
| **交互方式** | `chat` 对话 · `upload` 文件上传（Excel/CSV） · `form` 表单（设定调查范围与规则参数） · `voice` 语音输入（Web Speech API，不可用时优雅降级为文本） · `api` RESTful 接口 |

### 4.1 chat 对话：自然语言描述调查主题

数据聚合台顶部提供「用一句话描述调查主题」输入框。系统以**词典/规则匹配**（不调用任何模型服务）从描述中抽取：

| 抽取项 | 支持写法示例 |
|---|---|
| 主体 | `S028`、`安徽宏远机电设备有限公司`（按编码精确命中优先，其次按名称包含） |
| 期间 | `2026年`、`2026年3月`、`2026年第2季度`、`2026-01-01 至 2026-06-30` |
| 金额 | `50万元以上`、`10万到50万`、`不超过200万元` |
| 链条 | 采购/付款→采购付款链、销售/收款→销售收款链、报销/费用→费用报销链、银行/流水→资金流链、研发→研发投入链、税务/发票→税务申报链 |

解析结果**回填到筛选条件表单**，由调查人员确认或调整后执行；无法识别时明确提示补充条件，不用推测填补。

### 4.2 upload 文件上传：辅助数据导入

支持拖拽或选择文件导入：

| 文件类型 | 解析方式 |
|---|---|
| CSV（UTF-8） | 浏览器本地解析（支持引号转义、BOM） |
| CSV（GBK） | 自动检测编码异常后按 GBK 重读 |
| Excel（.xlsx/.xls） | 按需加载 CDN SheetJS 解析；离线不可用时提示另存为 CSV（不静默失败） |

导入后输出**解析摘要**：行数、涉及主体、金额区间与合计、日期跨度、列名映射情况（未识别的列原样保留并标注）、数据样例，并附溯源轨迹。

> **上传数据仅在本次会话内使用，不写库、不上传外部，且不参与规则命中判断**——它作为线索补充材料（举报材料整理表、外部对账单等）供调查人员参考。

## 五、技术架构

### 5.1 架构模式

采用 **架构 II：前端 + 数据预加载 JSON**，并叠加一层**可选的后端安全代理**：

```
┌─────────────────────────────────────────────┐
│  index.html（单文件，CSS/JS 全内联）          │
│  ├─ form 表单 / chat 对话 / upload / voice   │
│  ├─ PRELOAD_DEMO 演示数据集（内联）            │
│  ├─ 规则引擎 + 评分卡 + 证据核对（纯 JS 计算）  │
│  └─ 表格 / 图表 / 报告 / 溯源轨迹渲染          │
└───────────────┬─────────────────────────────┘
                │ 无凭据请求（X-Wuyan-Mode 头）
                ▼
┌─────────────────────────────────────────────┐
│  server.js 后端安全代理 :3001                  │
│  ├─ SQL 只读闸门（仅 SELECT + 表白名单 + LIMIT）│
│  ├─ 连接池（limit 10 / timeout 10s / 30s）     │
│  └─ 凭据仅存于 process.env                     │
└───────────────┬─────────────────────────────┘
                ▼
        MySQL datatest（26 张业务表，只读账号）
```

```

├── start.bat               ← 一键启动（检查环境→装依赖→起服务→开页面）
├── package.json

│   ├── core.js             ← 规则库 / 口径字典 / 评分卡 / 问答词典 / 报告模板
│   ├── demo.js             ← PRELOAD_DEMO 演示数据集生成器（固定种子，可复现）
│   ├── engine.js           ← 分析引擎（聚合/信号/线索/评分/证据/报告/问答/提醒）

│   ├── runtime.js          ← API 客户端 / 表格 / 图表 / 溯源轨迹 / 离线引擎兜底

    ├── build.js            ← 构建 index.html（内联 CSS/JS）
    ├── selftest.js         ← 自检（137 项：文件/数据/引擎/交互/合规/安全闸门/UI）
    ├── apitest.js          ← 接口验收（50 项，真实 HTTP 调用全部端点）
```

修改 `web/` 或 `app/` 下源码后，执行 `node tools/build.js` 重新生成 `index.html`。

### 5.3 关键设计决策

- **单文件交付**：`file://` 协议下浏览器禁止 `fetch` 本地文件，因此 CSS/JS/数据全部内联，保证双击即开、迁移整个文件夹不丢功能。
- **纯本地确定性计算**：全部风险识别、勾稽比对、评分均由规则引擎 + JS 计算完成，**不调用任何大模型服务**，结果可复现、可追溯、可审计。
- **离线优雅降级**：后端不可达时，前端自动切换到本地引擎（等价计算），功能完全可用。
- **数据质量预检**：当某规则的命中率超过 30%（如进项发票普遍无法追溯入库单），说明是数据口径/主数据维护问题而非舞弊信号，系统会将其转为**数据质量提示**并明确说明原因，避免逐条输出淹没真实线索。

### 调用示例

```bash

```

### SQL 安全闸门

代理层对 SQL 做白名单校验，以下均被**拒绝并记录到 `security.log`**：

- 非 `SELECT` 语句（`insert|update|delete|drop|alter|truncate|grant|create|replace|merge|call|execute|lock|rename|revoke`）
- 多语句（分号拼接）、注释绕过
- 非白名单表（如 `mysql.user`、`information_schema.*`）
- 危险函数（`load_file`、`outfile`、`dumpfile`、`sleep`、`benchmark`）
- 无 `LIMIT` 自动补齐 `LIMIT 5000`；超过 5000 行自动收敛

## 七、数据库连接

### 7.1 连接信息

凭据**仅存于服务端**（`server.js` 默认值或环境变量），**绝不写入任何前端文件**。

| 项 | 值 |
|---|---|
| 类型 | MySQL |
| 地址 | `115.190.168.89:3306` |
| 数据库 | `datatest` |
| 账号 | `readonly_user`（**只读**，严禁任何写操作） |
| 字符集 | `utf8mb4` |
| 连接池 | `connectionLimit: 10`，`connectTimeout: 10000`，查询超时 30s |

### 7.2 环境变量覆盖

```bash
DB_HOST=... DB_PORT=3306 DB_USER=... DB_PASS=... DB_NAME=datatest node server.js
```

可调参数：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `3001` | 服务端口 |
| `DB_POOL` | `10` | 连接池上限 |
| `MAX_ROWS` | `5000` | 前端单次查询返回上限 |
| `MAX_TABLE_ROWS` | `50000` | 分析引擎单表拉取上限 |
| `DATA_TTL_MS` | `300000` | 实时数据集缓存时间（0 = 每次重新读取） |
| `SYSTEMIC_RATE` | `0.3` | 数据质量“系统性缺陷”判定阈值 |
| `ENABLE_LLM` | `false` | 可选增强项，默认关闭 |

### 7.3 26 张业务表

## 九、合规与边界

### 9.1 助理不得替代的决策

是否**立案**、是否**扩大调查范围**、是否**移交**；异常是否**构成舞弊**；可疑等级最终判定、**责任人**认定、损失金额认定；是否采纳参考分值；报告最终结论与对外口径；涉及**法律、监管报送、纪律处分**的任何判断。

### 9.2 边界铁律

1. 输出**不得**出现"确认存在舞弊""构成舞弊""系某某所为""应认定为……"等定性结论
2. 输出**必须**使用分级表述："高度可疑/中度可疑/低度可疑/信息不足待补充"，并附加"供调查人员判断"
3. 证据不足时**必须**明示"当前数据不足以支持判断"，不得以推测填补
4. **不得**自动触发任何对外发送、报送、移交动作

### 9.3 系统的技术保障

- 全文渲染前经 `sanitizeText()` 过滤禁用定性词；报告生成后自动执行禁用词自检
- 问答模块对"是否构成舞弊/立案/移交/责任人/处罚"等超范围问题**强制拒答**，并引导至专业判断
- 报告导出仅提供 HTML / Markdown / CSV / 打印，**无"直接发送"类功能**
- 待办「标记已办」仅记录本地状态，不触发任何对外动作

### 9.4 无大模型依赖

**本项目不内置大模型 API，核心分析不依赖任何大模型服务。**

- 默认运行模式：**纯本地确定性计算**（规则引擎 + JS 计算）
- 文本生成：模板引擎 + 规则拼装（模板内联于 `core.js`）
- 问答能力：关键词/规则匹配 + 口径字典，非开放式对话
- 可选增强项 `ENABLE_LLM=true`：仅允许用于①报告文本润色 ②问题意图分类，**严禁**用于生成可疑等级、风险信号判定、证据差异结论等判断性内容；关闭时所有功能完整可用

## 十一、常见问题

**Q：双击 `index.html` 后顶部显示"后端未连接 · 本地离线引擎"，正常吗？**
正常。这说明后端服务未启动，系统自动使用内联演示数据 + 本地引擎，全部功能可用。如需连接真实数据库，请双击 `start.bat`。

**Q：选择"连接数据库"后提示已降级为演示数据？**
说明后端可达但数据库连接失败。请检查网络、数据库服务状态与账号权限；后端窗口会打印具体原因，也可访问 `/api/health` 查看。

**Q：真实数据跑出来信号很少或很多？**
两处机制会调节结果：
1. **数据质量预检**——某规则命中率超过 30% 时判定为系统性口径问题，转为数据质量提示而非逐条信号（页面会明确列出被转换的规则及原因）
2. **规则参数**——阈值可在「筛选条件」表单中调整；通过 API 调用时可传 `ruleParams` 覆盖

**Q：如何修改规则阈值？**
编辑 `app/core.js` 中 `RULES` 数组的 `param`，或通过 API 传入 `ruleParams: { "R01": { "amount": 3000000 } }`。修改后执行 `node tools/build.js` 重新构建。

**Q：语音输入不可用？**
语音输入依赖浏览器 Web Speech API。不支持时会自动禁用麦克风按钮并降级为文本输入，不影响其他功能。Chrome / Edge 支持较好，需允许麦克风权限。

**Q：自然语言描述识别不准怎么办？**
解析采用词典/规则匹配，不是语义理解。若识别结果不符，可直接在「筛选条件」表单中修正——解析只是把条件回填到表单，不会绕过人工确认直接改变调查范围。支持的主体写法见 §4.1。

**Q：上传 Excel 提示解析库不可用？**
Excel 解析依赖按需加载的 CDN 资源（SheetJS）。断网或 CDN 不可达时，请将文件另存为 **CSV（UTF-8 或 GBK）** 后重新上传；CSV 走浏览器本地解析，无任何外部依赖。系统不会静默失败。

**Q：数据会上传到外部吗？**
不会。演示模式全部计算在浏览器本地完成；连接数据库模式下，浏览器仅向本机 `127.0.0.1:3001` 发送无凭据请求，由本机代理访问只读数据库。系统不接入任何第三方服务。
